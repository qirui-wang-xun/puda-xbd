================================================
Prepared 2026-10-18. This document is intended to be given directly to Codex
on the destination server. Follow the actual repository code if diagnosing a
problem; do not silently substitute a different PUDA implementation.

1. User objective and authorization
----------------------------------
Deploy the uploaded experiment and run complete Wildfire experiments for
seeds 922, 923, 924, sequentially. Each seed trains stage1 from ImageNet for
50 epochs, generates fresh U pseudo labels from its own stage1 LAST model,
then trains the corrected stage2 for 50 epochs. Report final test OA and F1
for external damage class 0. Keep every seed's logs and checkpoints.

Inspect the destination machine, choose a writable deployment directory,
download, verify, unpack, test, then launch durable training. Do not merely
provide commands and stop if the user has asked you to deploy and run it.
Ask the user only for missing credentials, required scheduler/account choices,
or an incompatible platform. Never request tokens in chat or print them.
Do not stop existing jobs or modify drivers without separate authorization.

3. Destination prerequisites
----------------------------
- Linux x86_64 compatible with the packed environment and its system libraries.
- NVIDIA CUDA-capable GPU with compatible driver. Packed environment has
  Python3.10, PyTorch2.10.0+cu128. Packing does NOT include the driver.
- git, tar, sha256sum, bash, realpath, tmux (for non-scheduled servers).
- GitHub CLI gh for private repo/Release access. Install separately if absent.
- Sufficient disk space: environment unpacked about8.1GB, compressed about4.5GB;
  split pieces and combined archive temporarily occupy space together.
  Prefer at least40GB free initially, more for outputs and retained artifacts.
- Original local GPU was RTX4000Ada20GB; stage1 batch16+P16 completed multiple
  full runs, with PyTorch peak allocation about10.51GiB. Allow extra headroom.
- workers=6 per DataLoader; stage1 has source and target loaders concurrently.
  Do not confuse these workers with parallel experiments.

If this is a Slurm/HPC server, run GPU checks and training in an allocated GPU
job, not on a login node. Adapt submission wrapper, not scientific parameters.
The launcher runs ALL THREE seeds sequentially and may exceed a job walltime.
It can take one seed argument; for limited walltime use separate sequential
jobs or handle the two stages explicitly. Checkpoint resume is NOT implemented.

8. Complete training
--------------------
The launcher provides all important paths explicitly, overriding old local
path defaults. Do not run train_xbd.py with bare defaults on the new server.

For a non-scheduled GPU server, create a tmux session:
  tmux new -s puda-wildfire
Inside that session (set DEPLOY again if opening a separate shell):
  export DEPLOY="$HOME/puda-deploy"
  source "$DEPLOY/envs/PU/bin/activate"
  cd "$DEPLOY/code"
  RUN_ROOT="$DEPLOY/outputs/wildfire_$(date +%Y%m%d_%H%M%S)"
  bash run_wildfire.sh "$DEPLOY/data" "$DEPLOY/assets/resnet50-19c8e357.pth" "$RUN_ROOT"

This runs922 stage1 ->922 stage2 ->923 stage1 ->923 stage2 ->924 stage1 ->924 stage2.
Detach tmux with Ctrl-b then d; reattach with tmux attach -t puda-wildfire.
For a single seed, append922 (or923/924) to the launcher arguments.

Use the same command inside an approved GPU batch job on a scheduled server.
Do not launch concurrent copies onto the same GPU by default.

9. Fixed experimental settings
------------------------------
- P=400 sampled damaged examples from target train; U=ALL external U images.
- external damage0: destroyed + major-damage.
- external non-damage1: minor-damage + no-damage.
- PUDA internal positive is1. Evaluation converts back; F1 positive_label=0.
- Wildfire prior0.7886; seeds922/923/924.
- Stage1 batch16 + extra P16; P sampled from the fixed400 pool.
- Stage1 epochs50, lr1=0.0016102287018430657.
- Stage1 original losses, reconstruction behavior and training-mode behavior
  retained, including the original final-incomplete-batch skip AFTER forward.
  Do not silently add unrelated stage1 algorithm fixes.
- workers6; no AMP in this PUDA implementation (FP32).
- Stage1 last generates fresh pseudo probabilities for ALL U in eval/no_grad,
  threshold>0.5 means INTERNAL positive1; no historical accumulation/filtering.
- Add the exact same400 known P via p_samples.json, never resample P at stage2.
- Stage2 starts from ImageNet encoder + new classifier, NOT stage1 weights.
- Stage2 epochs50; batch16; lr2=0.00012266834924870657.
- Stage2 SGD encoder no momentum, classifier momentum0.9; weight_decay0.0005.
- Stage2 zero_grad each batch; train mode each epoch; evaluation restores modes.
- StepLR step_size35 gamma0.0035, once per EPOCH.
- Original resize256, center crop221, ImageNet normalization retained.
- Last epoch is the primary reported result. Best OA retained separately.
- This is an adapted/corrected PUDA baseline, not an exact upstream reproduction.

11. Failure handling
--------------------
- Keep full traceback/logs. Never report a dead tmux pane as active training.
- Check actual training process + advancing logs before claiming progress.
- First-stage decoder has max_unpool2d nondeterminism warning; warn_only=True
  allows it. This warning alone is not training failure.
- NVML driver/library mismatch is a server driver issue; CUDA imports can work
  despite broken nvidia-smi. An allocator NVML assertion can obscure an OOM.
- Keep batch16+16 for comparability; do not silently change batch size, lr,
  precision, prior, labels, P pool or loss functions to make it run.
- NaN loss/thresholds are invalid. Stop the affected job, preserve evidence,
  diagnose, and report before changing scientific settings.
- No general checkpoint RESUME implementation is provided. last.pt is not a
  full optimizer/RNG/dataloader resume state. Do not invent --resume flags.
- If stage1 completed but stage2 failed, run train_stage2_from_last.py using the
  existing stage1_last.pt and p_samples.json, with a fresh stage2 output path.
  This restarts stage2 from its defined initialization, not a mid-epoch resume.
- Both parsers expose --help. run_wildfire.sh is the authoritative paired call.
